# W102 report

## Решение по владельцу

Выбран минимальный вариант из `docs/TABS-NOTES.md`: не менял IPC для передачи
`tabId`, потому что Rust уже получает только метку окна, а payload событий уже
содержит путь и фронтенд сопоставляет его с вкладкой. `FileWatcher` теперь
хранит множество путей для каждой метки окна (`HashMap<String,
HashSet<PathBuf>>`), поэтому добавление второй вкладки не замещает первую;
повторная регистрация пути идемпотентна. Счётчик `roots` по-прежнему делает
один системный watcher на каталог, а дедупликация событий учитывает путь,
чтобы два изменения в одном debounce-пакете не склеивались в одно событие.

`AppState.open_files` теперь хранит множество меток окон для каждого пути
(`HashMap<PathBuf, HashSet<String>>`). Это сохраняет сведения о файле, когда
один и тот же путь открыт в нескольких окнах (например, при отключённом
`raiseExistingWindow`), и закрытие одного окна удаляет только его владение;
снимок файла удаляется лишь после ухода последнего владельца. Открытие из
проводника и маршрутизация по-прежнему выбирают/создают окно согласно
`raiseExistingWindow`; tab id остаётся фронтендной деталью.
