# W61 — UI Automation и TC-09/TC-10

## Фактическое дерево UI Automation

Снятый иерархический UIA tree сохранён в [ui-automation-tree-1.0.4.txt](ui-automation-tree-1.0.4.txt). Захват стартового экрана дождался доступности веб-содержимого: корневое окно имеет тип `ControlType.Window`; плитка `Markdown .md` отображается как `ControlType.DataItem`, класс начинается с `tile`, границы — `(578, 627, 140, 77)`. После `Ctrl+F` панель — `ControlType.Window` с именем `Find and replace` и классом `find-panel…`; поле — `ControlType.Edit` с именем `Search query`.

По этим данным `qa/acceptance.ps1` теперь ищет элементы по подстроке имени вместе с типом и классом. Для плитки добавлен резервный путь на случай пустого UIA имени: выбирается первый по экранному порядку `DataItem` класса `tile`, что соответствует Markdown в наблюдённом Format grid. TC-10 теперь ждёт появления CodeMirror `Edit`-элемента класса `cm-content…`, прежде чем отправить `Ctrl+F`, затем проверяет и панель, и поле поиска.

## Единственный полный прогон

Запущен один полный прогон текущего тогда набора из десяти сценариев. Он завершился `8/10`: TC-01—TC-08 прошли; TC-09 и TC-10 упали.

| Сценарий | Результат | Наблюдение |
| --- | --- | --- |
| TC-01 | PASS | Окно без аргументов и заголовок `MarkNote`. |
| TC-02 | PASS | Открылся `showcase.md`. |
| TC-03 | PASS | Открылся `cp1251.txt`. |
| TC-04 | PASS | Несуществующий путь не завершил процесс; окно осталось видимым. |
| TC-05 | PASS | Повторный запуск с тем же файлом завершился, остался один процесс. |
| TC-06 | PASS | Открыты отдельные окна `showcase.md` и `crlf.md`. |
| TC-07 | PASS | `big-10k.md` открылся, процесс отвечал. |
| TC-08 | PASS | `logo.png` отклонён с сообщением об открытии бинарного файла как текста. |
| TC-09 | FAIL | Стартовый экран закрылся и редактор появился, но после Ctrl+V счётчик остался `0 chars`; диалог закрытия сценарий поэтому не достиг. |
| TC-10 | FAIL | Заголовок `showcase.md` появился, но сценарий проверил редактор до его монтирования и закончил до отправки `Ctrl+F`. |

После прогона отдельная диагностическая попытка ввода также оставила `0 chars` и после Ctrl+V, и после `SendKeys`. Другой живой диагностический захват показал, что после фокусировки редактора `Ctrl+F` открывает панель с доступным UIA полем `Search query`. Это указывает на ненадёжность синтетического ввода для TC-09 и на гонку готовности редактора в прежнем TC-10.

TC-09 удалён из будущего автоматического набора и перенесён в [CHECKLIST.md](CHECKLIST.md) с шагами проверки ненулевого счётчика, диалога `Save changes?`, сохранения текста при `Cancel` и закрытия через `Discard`. Теперь будущий набор содержит девять автоматических сценариев; после единственного разрешённого полного прогона обновлённые девять сценариев и ожидание редактора в TC-10 не запускались повторно. Исторический результат 8/10 и подробный журнал сохранены в `acceptance-summary.json` и `acceptance-journal.jsonl`.

В W61 было четыре прямых диагностических запуска приложения; один остановился из-за ошибки в диагностическом PowerShell helper до чтения UIA, остальные использовались для дерева и проверки ввода/поиска. Был выполнен ровно один полный приёмочный прогон; он открыл 11 видимых окон по своим сценариям. Все процессы `marknote` после проверки завершены.
