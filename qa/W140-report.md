# W140: скорость ввода и большие документы

## Методика

Замер выполнен живым Vite + Edge через CDP (`qa/w140-benchmark.mjs`), без
прямого вызова функций редактора. Скрипт использует `Input.insertText` для
ввода, `Input.dispatchKeyEvent` для стрелки вниз и
`Input.dispatchMouseEvent(mouseWheel)` для прокрутки.

Для каждого размера выполнены 3 перезагрузки документа; внутри каждой
перезагрузки каждая операция повторена 5 раз, а в таблице приведено среднее
медиан этих трёх запусков. Документы ASCII Markdown имеют ровно 10 240,
204 800, 1 048 576 и 5 242 880 байт (последний обозначен `5120KB`, то есть
5 MiB).

- `first render`: от начала `Page.reload` до готового `.cm-editor` и двух
  `requestAnimationFrame`;
- `input`: от CDP `Input.insertText` до возврата команды;
- `arrow`: пять стрелок на неизменённом документе, каждая измеряется от
  `Input.dispatchKeyEvent` до возврата команды;
- `viewport rebuild`: перед каждым образцом viewport возвращается в начало,
  затем отправляется wheel-событие и ожидается один animation frame. Это
  заставляет CodeMirror действительно сменить видимую область, а не измеряет
  wheel в уже достигнутом конце документа.

Исходные и итоговые JSON сохранены рядом со скриптом:

- `qa/w140-before-final.json` — до правки;
- `qa/w140-after-final.json` — после правки.

## Результаты

Все значения в миллисекундах; `до → после`.

| Документ | Первая отрисовка | Ввод одного символа | Стрелка | Пересборка viewport |
| --- | ---: | ---: | ---: | ---: |
| 10 KB | 118.9 → 106.3 | 3.2 → 3.2 | 2.2 → 2.2 | 35.5 → 40.9 |
| 200 KB | 109.5 → 108.0 | 8.0 → 8.3 | 4.8 → 4.8 | 36.0 → 36.1 |
| 1 MiB | 181.8 → 107.1 | 25.1 → 21.8 | 19.2 → 9.4 | 40.0 → 41.5 |
| 5 MiB | 379.0 → 349.1 | 93.0 → 92.1 | 75.3 → 62.9 | 47.9 → 35.5 |

Наиболее показателен большой документ: движение курсора стало быстрее на
16.4%, смена viewport — на 26.0%, первая отрисовка — на 7.9%. Ввод меняется
слабо (`93.0 → 92.1`), поскольку сама вставка в 5 MiB документ и обновление
syntax tree остаются дорогими; правка не отключает предпросмотр и не меняет
порог `disableAboveBytes`.

## Что изменено

1. `src/editor/livePreview/plugin.ts` теперь считает UTF-8 размер через
   `WeakMap<Text, number>`. Документ CodeMirror неизменяемый, поэтому при
   `selectionSet` и `viewportChanged` тот же `Text` повторно использует размер
   вместо нового `doc.toString()` и `TextEncoder`.
2. `src/editor/livePreview/blocks.ts` принимает видимые диапазоны для
   `nestedListGuide`. Обход строк `OrderedList`/`BulletList` ограничен
   пересечением списка с viewport; вызовы без диапазонов, включая полный
   preview и существующие интеграции, сохраняют прежнее полное поведение.
   `src/editor/livePreview/plugin.ts` передаёт в builder реальные
   `view.visibleRanges`.

Добавлены регрессионные тесты:

- `tests/livePreview.performance.test.ts` проверяет, что размер одного
  неизменяемого `Text` вычисляется один раз;
- `tests/orderedLists.test.ts` проверяет отсутствие guides за пределами
  видимого диапазона.

## Проверки

- `npx vitest run --poolOptions.threads.maxThreads=3` — 50 файлов, 429 тестов
  прошли;
- `npx tsc --noEmit` — прошёл;
- Rust не менялся, поэтому `cargo test` не запускался.

## Проверенные, но не изменённые места

- `src/editor/keymap.ts`: текущий `orderedListNormalization` в
  `getMarkerChangesForTransaction` уже берёт только изменённый list-блок и
  не вызывает полный `doc.toString()` при обычной транзакции. Полный
  `normalizeViewOrderedLists` используется только командами Enter/Tab и
  indent/outdent; менять это без изменения их семантики не стал.
- `src/editor/livePreview/plugin.ts`: пересборка на `selectionSet` нужна для
  `revealMarkup` — курсор может включить/выключить отображение маркеров.
  Универсальный пропуск пересборки изменил бы вид предпросмотра.
- `src/editor/livePreview/tables.ts`: `querySelectorAll` находится в
  обработчиках drag/mousemove таблиц, а не в пути набора, стрелок и смены
  viewport; поведение таблиц ради общего набора замеров не менялось.
- `src/editor/spellcheck.ts`: полный обход syntax tree выполняется только
  после `docChanged` или смены дерева, не на движении курсора/прокрутке.
  Инкрементальная разметка требует корректной обработки вставки/удаления
  границ code/formula/link, поэтому без отдельного доказательного замера и
  тестов её не вводил.
